feat(skills): mirror the reference registration and expose its outcome

Answering 'why is the skill not in the skill list': the running host was started at
22:23 and the bundle was rebuilt at 22:32, so the registration code had never been
loaded. Verifying with the skill tool returned 'unknown skill', which settles it.

While checking, two real defects in my own registration came out:
- it was not wrapped in sctx.effect, unlike the reference dsh matlab-mcp plugin, so
  the provider was never torn down with the plugin
- /diagnostics could not answer 'did it register?', so the only signal was the skill
  list

Now the inject is an effect (same shape as the reference), and the registration
outcome (attempted / registered / error / names) is reported by
/api/dsh-eda-mcp/diagnostics under 'skills'.

Plugin code only takes effect on the next DSH start; a bridge reconnect does not
reload it.
