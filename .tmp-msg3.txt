fix(tools): launch JLCEDA through explorer; document that it ignores the project argument

Live experiments on the same executable:
- spawning lceda-pro.exe directly (and PowerShell Start-Process with the same
  arguments/working directory as the official shortcut) makes it exit with code 0
  immediately: no window, no child process, debug.log untouched
- handing the launch to the desktop shell (explorer.exe running a small .cmd with
  start "" "<exe>" "<project>") starts it normally: 5 processes, window, and the
  extension connects within ~9 s
- the project path is still ignored by the app (active document stays HOME), both
  on a fresh start and against a running instance

Windows launches now go through explorer; other platforms spawn directly. The
result reports via=explorer|direct plus projectOpenedByArgument=false and a
projectNote, so callers cannot assume the project was opened.

Also note: DMT_Project only offers openProject(projectUuid) for workspace projects;
there is no path-based open API, so opening a local .eprj2 by API is not possible.

3 new unit tests cover the launch script (echo off, quoted paths with spaces,
with/without project).
